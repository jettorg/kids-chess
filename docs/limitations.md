### 2. 실제 아이패드 사파리에서 검증하지 못했다

**현상** — 모든 검증은 크로미움과 WebKit(데스크톱 사파리 엔진)으로 했습니다. 실제 iOS 사파리는 WebAudio 가
사용자 제스처 안에서만 시작되고, 홈 화면 앱의 저장소 정책이 다릅니다. WebKit E2E 가 추가돼 엔진 차이는 잡히지만
iOS 고유 동작은 여전히 미확인입니다.

**보완** — 실제 기기에서 아래 목록을 한 번 확인합니다.
- 첫 탭에서 효과음이 나는지 (안 나면 `sound.ts` 의 `ctx()` 를 첫 pointerdown 에서 미리 호출)
- 홈 화면에 추가 후 전체 화면으로 열리고 판 아래가 잘리지 않는지
- 비행기 모드에서 앱이 열리는지
- 일주일 이상 안 쓴 뒤 진행 기록이 남아 있는지 (홈 화면 앱은 7일 규칙에서 예외)
- 드래그 중 화면이 스크롤되지 않는지
- ❔ 도움 창의 "복사" 가 동작하는지 (iOS 는 클립보드 권한이 까다로움)

앱스토어 배포까지 생각한다면 Capacitor 로 감싸는 방법이 있습니다.

### 10. 동기 부여 요소가 없다

**현상** — 레슨과 퍼즐에 완료 표시와 추천 난이도만 있습니다. 상용 아이용 앱은 별, 배지, 연속 기록, 진행 막대로 계속 하게 만듭니다.

**보완** — 퍼즐마다 힌트 없이 풀면 별 3개, 힌트 1번 2개, 정답 보기 1개처럼 점수를 두고, 도감 옆에 "내 기록" 화면을
만듭니다. 기록 옮기기 코드에 함께 담으면 됩니다. "오늘의 퍼즐 3개" 같은 일일 목표가 가장 효과가 큽니다.

### 13. GitHub Pages 는 응답 헤더를 못 바꾼다

**현상** — COOP/COEP 헤더를 못 붙여 `SharedArrayBuffer` 를 쓸 수 없습니다. 멀티스레드 Stockfish 나 워커 간 공유
메모리는 불가합니다. 서버가 없으니 계정·랭킹도 불가합니다.

**보완** — 필요해지면 Cloudflare Pages 나 Vercel 로 옮깁니다. `base: './'` 덕분에 코드 변경 없이 옮겨집니다.

### 15. 커밋 이력에 빈 커밋 3개

**현상** — Pages 권한 문제를 풀 때 배포를 다시 걸려고 만든 빈 커밋(`a7b741e`, `6906b84`, `2b2af97`)이 남아 있습니다.

**보완** — 혼자 쓰는 저장소라면 `git rebase -i e75bcab` 로 지우고 `git push --force-with-lease` 하면 됩니다.
공개된 이력을 다시 쓰는 것이므로 다른 사람이 받아간 뒤에는 하지 않는 편이 좋습니다.

### 16. 시각 회귀 테스트는 로컬에서만 돈다

**현상** — `e2e/visual.spec.ts` 의 기준 이미지는 macOS·크로미움 기준입니다. 리눅스 CI 는 글꼴과 렌더링이 달라
같은 기준을 쓸 수 없어 `VISUAL=1` 일 때만 실행합니다.

**보완** — CI 에서 한 번 `--update-snapshots` 로 리눅스 기준 이미지를 만들어 저장소에 넣거나, 로컬에서도 CI 와 같은
Docker 이미지(`mcr.microsoft.com/playwright`)로 돌려 기준을 통일합니다. 후자가 유지가 쉽습니다.

### 17. 엔진이 여전히 순수 JS 배열 기반이다

**현상** — 초당 13만~22만 노드. 복잡한 중반에서 부엉이(60만 노드)는 깊이 5 에 그칩니다. 아이용으로는 충분하지만
어른을 이기는 수준은 아닙니다.

**보완** — 다음 단계는 (1) 킹 위치 캐시로 `isInCheck` 의 킹 탐색 제거, (2) 잡기 전용 수 생성기로 정지 탐색 비용 절감,
(3) Zobrist 키 기반 반복 검출. 그 이상은 비트보드 재작성이거나, 최상위 난이도에 Stockfish WASM(단일 스레드) 을 붙이는
방법입니다.
