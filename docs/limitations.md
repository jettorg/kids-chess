# 알려진 한계와 보완 방법

[English](limitations.en.md)

2026-09-27 기준. 상용 수준 검토를 마친 뒤 남은 한계를 근거와 함께 적고, 각각을 어떻게 보완할지 정리한 문서입니다.
우선순위는 아이가 실제로 겪을 가능성과 고치는 비용을 함께 본 것입니다.

## 각 항목

### 1. 대화상자에 초점 가두기가 없다

**현상** — 결과 창과 승격 선택 창이 열려도 키보드 초점이 창 안으로 옮겨가지 않고, Tab 을 누르면 뒤에 가려진 화면으로 초점이 빠져나갑니다. axe 자동 검사는 초점 관리를 보지 않아 100점이 나왔지만 실제 키보드 사용자는 막힙니다.

**보완** — `src/ui/dialogs.ts` 에서 창을 열 때 첫 버튼에 `focus()`, Tab 과 Shift+Tab 을 창 안에서 순환시키고, 닫을 때 원래 초점으로 되돌립니다. 컨테이너에 `role="dialog"`, `aria-modal="true"`, `aria-labelledby` 를 붙입니다. E2E 에 "승격 창이 열리면 Tab 이 창 밖으로 나가지 않는다" 테스트를 추가합니다.

### 2. 실제 아이패드 사파리에서 검증하지 못했다

**현상** — 모든 검증은 크로미움(데스크톱·모바일 뷰포트 에뮬레이션)으로 했습니다. iOS 사파리는 WebAudio 가 사용자 제스처 안에서만 시작되고, 홈 화면 앱의 저장소 정책이 다르며, `dvh` 는 iOS 15.4 이상에서만 됩니다.

**보완** — 실제 기기에서 아래 목록을 한 번 확인합니다.
- 첫 탭에서 효과음이 나는지 (안 나면 `sound.ts` 의 `ctx()` 를 첫 pointerdown 에서 미리 호출)
- 홈 화면에 추가 후 전체 화면으로 열리고 판 아래가 잘리지 않는지
- 비행기 모드에서 앱이 열리는지
- 일주일 이상 안 쓴 뒤 진행 기록이 남아 있는지 (사파리는 일반 사이트의 저장소를 7일 후 지울 수 있으나 홈 화면 앱은 예외)
- 드래그 중 화면이 스크롤되지 않는지

앱스토어 배포까지 생각한다면 Capacitor 로 감싸는 방법이 있습니다. 코드 변경 없이 같은 정적 파일을 담습니다.

### 3. 새 버전이 다음 실행 때 조용히 적용된다

**현상** — 서비스 워커가 새 빌드를 받아 두고 다음 실행에 적용합니다. 배포 직후 열려 있던 화면은 옛 버전으로 남고, 사용자는 새 버전이 있는지 알 수 없습니다.

**보완** — `src/main.ts` 에서 `registration.addEventListener('updatefound')` 를 듣고, 새 워커가 `installed` 가 되면 상태 줄에 "새 버전이 있어요 — 새로고침" 안내를 띄웁니다. 진행 중인 판이 없으면 자동 새로고침해도 됩니다. 서비스 워커의 `skipWaiting` 은 이미 켜져 있어 새로고침만 하면 바로 바뀝니다.

### 4. 탐색 엔진이 느리다

**현상** — 초당 약 3만 노드입니다. 부엉이(3.5초)가 초반에는 깊이 5, 복잡한 중반에는 깊이 4에 그칩니다. 원인은 `src/engine/moves.ts` 가 수를 둘 때마다 64칸 배열을 통째로 복사하고, 합법 수 판정을 위해 매번 수를 적용해 보는 구조이기 때문입니다.

**보완** (효과가 큰 순서)
1. **make/unmake** — 복사 대신 수를 두고 되돌리는 방식으로 바꾸면 보통 3~5배 빨라집니다. `Position` 을 가변으로 두고 되돌리기 정보를 스택에 쌓습니다. 엔진 테스트(perft 포함)가 그대로 안전망이 됩니다.
2. **Zobrist 해시** — 전치 테이블 키를 FEN 문자열 대신 64비트 해시로 바꿉니다. 지금은 노드마다 FEN 을 만듭니다.
3. **수 정렬 개선** — 킬러 무브와 히스토리 휴리스틱을 넣으면 같은 시간에 한 깊이 더 봅니다.
4. **의사 합법 수 생성** — 킹 안전성은 실제로 둘 때만 검사합니다.
5. 여기까지 하면 같은 예산에서 깊이 2 정도 더 봅니다. 그 이상은 비트보드로의 재작성이 필요하며, 아이용 앱에는 과합니다.

대안으로 Stockfish WASM 을 최상위 난이도에만 붙이는 방법이 있습니다. 약 10MB 를 받아야 하고, 멀티스레드 빌드는 13번 항목 때문에 GitHub Pages 에서 못 씁니다. 단일 스레드 빌드도 지금 엔진보다 훨씬 셉니다.

### 5. 난이도가 시간 예산이라 기기마다 세기가 다르다

**현상** — 곰 1.5초, 부엉이 3.5초로 정해져 있어 빠른 맥에서는 더 깊이 보고 느린 태블릿에서는 얕게 봅니다. 같은 "부엉이"인데 기기에 따라 세기가 다릅니다.

**보완** — `src/ai/ai.ts` 의 `LEVEL_SEARCH` 를 시간 대신 노드 수 예산으로 바꿉니다. `SearchContext` 에 이미 노드 카운터가 있어 `checkTime` 을 `checkBudget` 으로 바꾸면 됩니다. 응답 시간은 기기마다 달라지지만 세기는 같아집니다. 처음 실행 때 1초짜리 벤치마크로 노드 예산을 보정하는 절충안도 있습니다.

### 6. 정적 평가가 단순하다

**현상** — 재료 점수와 칸별 가산점만 봅니다. 잡을 것이 없는 조용한 국면에서 a6 같은 어색한 수를 둡니다. 실수를 벌하는 능력은 정지 탐색 덕에 괜찮지만, 계획이 없어 보입니다.

**보완** — 평가 함수에 기동력(합법 수 개수), 킹 안전(주변 폰 방패), 폰 구조(고립·중복 폰 감점), 통과 폰 가산을 더합니다. 칸 점수는 PeSTO 표처럼 공개된 값으로 바꾸고 초반·종반을 보간합니다. 각 항목을 켜고 끄며 자체 대국으로 승률을 비교하는 테스트를 `tests/` 에 두면 개악을 막을 수 있습니다. 초반 다양성은 열 수 정도의 간단한 오프닝 북으로 해결됩니다.

### 7. 퍼즐이 모두 "흰색 한 수 메이트"다

**현상** — 156개가 모두 같은 유형입니다. `scripts/import-puzzles.ts` 가 흑이 먼저 두는 문제와 두 수 이상 문제를 걸러내기 때문입니다. 또 Lichess DB 의 앞 40만 행에서만 골라 무작위성이 낮습니다.

**보완**
- **흑 차례 문제** — 판을 뒤집어 아이 쪽을 아래로 두면 됩니다. `puzzle.side` 필드를 추가하고 `startPuzzle` 에서 `flipped` 를 맞춥니다.
- **두 수 메이트** — 데이터의 `Moves` 에 상대 응수가 들어 있습니다. 아이가 첫 수를 두면 앱이 상대 응수를 자동으로 두고, 두 번째 수가 메이트인지 판정합니다. 상대 응수가 여러 개인 경우는 엔진으로 "어떤 응수에도 메이트가 있는지" 검증해 걸러냅니다 (`tests/search.test.ts` 의 `isForcedMateInTwo` 와 같은 방식).
- **주제별 묶음** — Themes 열의 fork, pin, hangingPiece 로 "공짜 말 잡기", "포크" 세트를 만듭니다.
- **표본 추출** — 전체 파일을 스트리밍하며 무작위 표본을 뽑도록 스크립트에 `--sample` 옵션을 더합니다.
- **적응형 난이도** — 연속 정답이면 레이팅을 올리고 틀리면 내리는 간단한 규칙을 진행 기록에 저장합니다.

### 8. 레슨이 말 움직임 6개뿐이다

**현상** — 배우기 화면은 "이 말로 검은 말을 다 잡기" 한 가지 목표만 지원합니다. 체크에서 벗어나기, 캐슬링, 앙파상, 승격, 기본 메이트 형태는 도감 글로만 있습니다.

**보완** — `src/data/lessons.ts` 의 레슨 형식에 목표 종류를 추가합니다: `capture-all`(지금), `reach`(특정 칸 도달), `escape-check`, `checkmate`, `castle`. 상대가 정해진 수를 두는 대본(`opponentMoves`) 을 허용하면 앙파상처럼 상대 수가 필요한 규칙도 가르칠 수 있습니다. 판정 로직은 `app.ts` 의 `checkLessonDone` 에 목표별 분기를 넣습니다. 레슨마다 짧은 말풍선 설명을 단계별로 보여주는 방식이 아이에게 맞습니다.

### 9. 진행 기록이 기기에만 저장된다

**현상** — 설정·진행·퍼즐 기록이 localStorage 에만 있어 태블릿에서 푼 퍼즐이 맥에는 안 보이고, 브라우저 데이터를 지우면 사라집니다.

**보완** (비용 순)
1. **내보내기·가져오기** — 진행 기록을 짧은 코드나 파일로 내보내고 다른 기기에서 붙여 넣습니다. 서버가 없어 개인정보 문제가 없습니다.
2. **가족 코드 동기화** — Supabase 나 Firebase 에 "가족 코드"를 키로 기록을 저장합니다. 로그인 없이도 되지만 코드가 유출되면 누구나 볼 수 있습니다.
3. **계정** — 아이 대상 서비스는 개인정보 규정(국내 만 14세 미만 법정대리인 동의)이 따라오므로 신중해야 합니다.

### 10. 동기 부여 요소가 없다

**현상** — 레슨과 퍼즐에 완료 표시만 있습니다. 상용 아이용 앱은 별, 배지, 연속 기록, 진행 막대로 계속 하게 만듭니다.

**보완** — 퍼즐마다 힌트 없이 풀면 별 3개, 힌트 1번 2개, 정답 보기 1개처럼 점수를 두고, 도감 옆에 "내 기록" 화면을 만듭니다. 모두 localStorage 로 충분합니다. "오늘의 퍼즐 3개" 같은 일일 목표가 가장 효과가 큽니다.

### 11. E2E 가 크로미움만 돈다

**현상** — `playwright.config.ts` 에 크로미움 프로젝트만 있습니다. 사파리(WebKit)와 파이어폭스의 차이(특히 `dvh`, 서비스 워커, 포인터 이벤트)는 자동으로 잡히지 않습니다.

**보완** — `projects` 에 `webkit` 을 추가하고 CI 의 설치 명령에 `webkit` 을 더합니다. 실행 시간이 두 배가 되므로 WebKit 은 레이아웃·PWA·조작 테스트만 돌리도록 `grep` 으로 좁힙니다. 화면이 달라지는 회귀를 잡으려면 `toHaveScreenshot` 으로 대국·배우기·퍼즐 화면의 기준 이미지를 저장합니다.

### 12. 움직임 줄이기 설정을 일부만 따른다

**현상** — 체크 깜박임과 흔들림은 `prefers-reduced-motion` 을 따르지만, 승리 색종이와 말이 미끄러지는 애니메이션은 따르지 않습니다.

**보완** — `confetti.ts` 시작부와 `board.ts` 의 `animateLastMove` 에서 `matchMedia('(prefers-reduced-motion: reduce)').matches` 면 건너뜁니다.

### 13. GitHub Pages 는 응답 헤더를 못 바꾼다

**현상** — COOP/COEP 헤더를 못 붙여 `SharedArrayBuffer` 를 쓸 수 없습니다. 멀티스레드 Stockfish 나 워커 간 공유 메모리는 불가합니다. 서버가 없으니 계정·랭킹도 불가합니다.

**보완** — 필요해지면 Cloudflare Pages 나 Vercel 로 옮깁니다. 둘 다 정적 파일에 헤더를 붙일 수 있고 비공개 저장소도 무료입니다. `base: './'` 덕분에 코드 변경 없이 옮겨집니다.

### 14. 오류 수집이 없다

**현상** — 현장에서 오류가 나도 알 방법이 없습니다. 의도적으로 아무 데이터도 보내지 않습니다.

**보완** — 아이용 앱이므로 기본은 "수집하지 않음"을 권합니다. 꼭 필요하면 개인정보 없는 오류 로그(스택과 앱 버전만)를 보호자 동의 옵션으로 켜는 방식이 맞습니다. 더 간단하게는 README 에 문제 신고 링크를 두고, 앱 안의 도움 화면에서 진단 정보(브라우저, 버전, 마지막 오류)를 복사할 수 있게 합니다.

### 15. 커밋 이력에 빈 커밋 3개

**현상** — Pages 권한 문제를 풀 때 배포를 다시 걸려고 만든 빈 커밋(`a7b741e`, `6906b84`, `2b2af97`)이 남아 있습니다.
